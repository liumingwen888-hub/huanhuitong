# 文档同步合同

状态：APPROVED。交付状态：READY。

## 单一权威

每个主题只允许一个完整权威来源，归属见 [authority-map.md](authority-map.md)。其他文件只保留必要摘要和相对链接，避免复制长规则造成漂移。外部研究只记录事实和来源；产品采用需要进入决策或领域文档。

换汇通项目内部权威文档保存在项目根目录中。所有导出的 ZIP、审查报告、验证报告、交接包及其他项目外生成物，统一输出到 `C:\Users\Administrator\Desktop\Codex`。不得散落到桌面根目录、Documents 根目录或其他项目目录。项目外产物必须记录来源任务、生成日期、相对内容清单、完整性校验和；ZIP 不得含绝对路径、`..` 路径、路径穿越项或项目根目录外文件。

## 任务开始

任何功能、缺陷修复、迁移或架构修改开始前，更新 [active-work.md](../status/active-work.md) 与对应计划，写明目标、授权、涉及文件、排除范围、风险、验收和预期验证。代码开发授权为 0 时只能规划，不能创建工程或实现。

## 任务完成前

按实际影响同步：

- 对应领域和架构权威文档；
- current、next、verification 与 progress-log；
- open-decisions 及需求追踪；
- 对应安全、测试和运维文档；
- 文档总索引。

若某类文档无需修改，完成报告必须给出原因。状态、计划与实现不得互相矛盾。

## 完成定义

代码任务只有同时满足实现、测试、安全检查、文档同步、索引有效、真实验证、Git 差异与计划一致、未完成项进入 next 或 open-decisions，才可标记 VERIFIED。规划任务则要求规定文档完整、相对链接有效、范围与状态一致、禁止项未出现，并有可重跑的验证记录。

废弃内容使用 REPLACED 并链接替代来源，不删除必要审计理由。不得把未来设想写成已实现事实。

## 大型计划文档治理

计划文件按职责和审核边界拆分，不按固定字符数机械截断：

- 普通计划 Markdown 的目标值为不超过 60KB 且不超过 1,500 行；
- 任一计划 Markdown 的硬上限判定为 `bytes > 100000 OR lines > 2500`，任一条件成立即失败并必须继续拆分；
- 每组拆分计划必须提供 `00-index.md`，说明状态、权威阅读顺序、文件职责、外部审核入口和断点接手方式；
- 巨型未来代码使用 canonical fragments 与 migration manifest，正文只保存一次；其他计划文件只通过相对链接、目标文件名和完整 SHA-256 引用；
- manifest 必须给出精确拼接顺序、各片段字节数/行数/SHA-256、完整目标字节数/SHA-256及可重跑的等价性验证；
- 外部审核先读索引，再按 finding 或变更范围读取对应架构、步骤、测试与 canonical fragment；
- 后续新计划从创建时执行本规则，不再形成万行单文件。

计划作者负责职责拆分、单一权威和 manifest；实施者只从 canonical fragment 重建目标；复审者按索引和 manifest 核验覆盖与字节等价；完成者在交付前验证尺寸、链接、UTF-8、fence、Secret、TEMP 和范围。
