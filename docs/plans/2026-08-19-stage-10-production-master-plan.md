# 阶段 10 生产级监控、备份、恢复演练和发布加固 总体规划

计划版本：`v0.1（需求确认中）`。计划状态：`DRAFT`。

基线：阶段 1–9 VERIFIED（阶段 9 于 2026-08-19 用户验收通过）。

## 目标

在已验证的九阶段能力之上完成**生产就绪闭环**：完整观测（指标/告警）、备份与恢复演练、灾难模式预案、发布门禁与容量基线——收尾"恢复不重复副作用"和"发布前核验"两大运维红线。

## 边界事实（P0-6）

- **真实部署目标**（云/主机/域名/TLS）：需用户提供——合成期以本地 Docker Compose 全栈编排代替验证。
- **真实告警通道**（PagerDuty/短信）：合成期以结构化告警事件 + 门禁断言代替。
- **生产容量压测**：合成期以容量基线文档 + 测试容器内基准代替。

## 核心设计决策（需确认）

1. **本地编排**：Docker Compose 单文件全栈（四服务 + 网络 + 卷）？
2. **观测**：OpenTelemetry SDK 已有接口（S1）——补指标注册与导出（合成期导出到日志，生产换 OTLP）？
3. **备份**：pg_basebackup + WAL 归档（物理）为主，逻辑备份（pg_dump）为辅——双轨？
4. **恢复演练**：自动化脚本（拉起临时容器→恢复→对账三域→断言无重复副作用→销毁）？
5. **发布门禁**：`pnpm release:gate` 聚合脚本（test:all + arch + docs + 安全扫描 + 迁移演练）？
