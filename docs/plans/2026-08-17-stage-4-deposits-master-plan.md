# 阶段 4 充值、确认、归集和链上对账 总体规划

计划版本：`v1.0`。计划状态：`READY`（2026-08-17 用户裁决：按建议值默认推进）。交付状态：`DESIGNING`。

基线：阶段 1–3 VERIFIED（2026-08-17 用户验收通过）。本文是阶段 4 需求确认与任务分解草案。

## 目标

在已验证的复式账本核心上建立**充值全链路**：链上地址生成与分配、充值检测、确认等待（含重组处理）、入账过账、归集（sweep）到平台主钱包、以及链上余额与账本余额的对账。完成后用户可以真实向平台地址转账并看到余额增加。

## 已裁决（2026-08-17 用户通过，按建议值默认）

- **P0-1/2/4**：以合成资产目录推进机制层（USDT-TRC20/USDT-ERC20/BTC/ETH/USD-FIAT），真实清单阶段 4 上线前另行裁决。
- **地址策略**：HD 钱包派生（BIP-44 路径）；私钥存储为接口层设计，实现推后（测试用假密钥，生产需独立授权）。
- **节点访问**：第三方 RPC 适配器接口（真实供应商未确定，测试用 fake 适配器）。
- **确认数**：TRON 19 / Ethereum 12 / Bitcoin 6（credential_policies 式版本化配置）。
- **归集策略**：金额阈值触发（可配置，定时批量作为补充模式）。

## 任务分解草案（v0.1）

| # | 任务 | 内容 |
|---|---|---|
| S4-1 | 地址领域合同与 V6 迁移 | deposit_addresses（uid/asset/network/address/path/状态）、address_assignments（幂等分配）、链上扫描检查点 |
| S4-2 | 地址生成与分配服务 | 按资产/网络生成唯一充值地址（HD 派生或独立密钥对）；显式幂等分配到 UID；地址复用策略 |
| S4-3 | 充值检测 Worker | 扫描链上新交易（节点/RPC 适配器接口）；匹配已分配地址；生成充值候选事件（含 txid/金额/确认数） |
| S4-4 | 确认等待与重组处理 | 按资产策略等待 N 确认；检测链重组（已入账交易被回滚→冲正）；UNKNOWN 状态不推断 |
| S4-5 | 充值入账编排 | 地址→UID→金额→S3-6 depositConfirmed 模板→PostMoneyService 过账；幂等（txid+网络唯一）；Outbox 通知 |
| S4-6 | 归集（Sweep）服务 | 从充值地址归集到平台主钱包；归集费用记账；归集交易状态跟踪 |
| S4-7 | 链上对账 | 链上地址余额 vs 账本余额定期对账（复用 S3-5 ReconciliationService 模式）；差异告警 |
| S4-8 | 威胁模型与阶段 4 验收 | 地址私钥安全、重组攻击、双花、金额精度、对账完整性验收 |

每任务按阶段 3 流程：详细计划 → 外部复审 → 授权 → TDD → 验证 → 文档同步。
