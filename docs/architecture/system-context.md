# 系统上下文

需求状态：APPROVED。交付状态：DESIGNING。

## 参与者与外部系统

- 终端用户：第一阶段通过 Telegram Bot，未来通过 Android/iOS App 访问同一平台 UID。
- 运营、客服、风控、财务与审计人员：通过管理后台执行受 RBAC、数据范围和 Maker-Checker 保护的操作。
- Telegram Bot API：提供 Update、Webhook、消息、按钮、深链和通知通道，不是身份或资金事实源。
- 区块链节点或托管基础设施：提供地址、交易、签名后广播与确认观察；链上状态需考虑节点分歧和重组。
- 法币代付供应商：通过适配器提供能力、报价、订单、回调、查询和对账。
- 合规及身份服务：生产门禁的一部分，真实供应商尚未确定。

## 系统边界

换汇通核心持有内部 UID、业务订单、复式账本、余额投影、风险决定、审批和审计。PostgreSQL 是业务与资金事实源。所有外部输入先经适配器验真、解析和幂等控制，再调用领域用例；所有外部副作用从 Outbox 或持久任务驱动。

Bot、App 与管理后台不能直接访问账本表或改余额。Signer 只接收已批准、最小化的签名请求，不理解业务规则；Broadcaster 只广播已签名交易；Confirmation Worker 独立观察权威结果。

## 核心不变量

每个资金动作可追溯到业务订单和幂等键；每个已过账交易借贷平衡；未知外部结果不被猜成成功或失败；一个 Telegram 绑定只解析到一个 UID；任何管理员操作均不能绕过服务端授权和审计。
