# 复式账本模型

需求状态：APPROVED。交付状态：DESIGNING。

## 核心结构

账本由账本账户、业务交易、分录、资产、订单关联和幂等资金命令组成。每个账本账户绑定一个所有者、资产、用途和正常余额方向。用途至少区分用户可用、用户冻结、用户在途、平台托管资产、用户负债、领取负债、费用收入、上游成本和清算差异。

每个过账交易分录总借方等于总贷方，资产内平衡；历史分录追加后不可更新或删除。余额投影是可重建读模型，不是独立资金事实。业务模块提交资金命令，由账本验证幂等、账户状态、资产、精度、余额与并发版本后原子过账。

## 金额规则

整数资产使用最小单位整数，领域使用 bigint 或专用金额类型。汇率和费率使用明确精度十进制；JSON 金额为十进制字符串；PostgreSQL BIGINT 与 NUMERIC 先按字符串读取。禁止 JavaScript number 和修改全局 BigInt.prototype.toJSON。舍入方向、余数账户和精度由资产/市场版本配置确定。

## 记账模板

- 充值：外部托管资产或应收清算账户对用户可用/在途负债；确认与重组分开过账。
- 内部转账：付款人可用负债减少，收款人可用负债增加；费用单独进入费用收入。
- 红包/领取：创建时从付款人可用转领取冻结负债；领取转接收人可用；退款转回付款人。
- 提现：申请时可用转冻结；成功时结算用户负债与托管资产，费用收入和链上成本分开；失败释放冻结。
- 换汇：卖出资产先冻结，成交时使用资产清算账户同时结算卖出与买入两条平衡腿，点差、手续费和上游成本分离。
- 法币代付：用户资产先冻结；成功后结算至供应商清算/应付账户；失败释放；冲正用反向新交易。

## 并发、冲正与对账

扣减使用数据库事务、账户锁或可证明等价的原子条件更新，禁止检查后写入竞态和负余额。资金命令以业务类型、订单 ID、操作类型和重试代次形成唯一幂等键。纠错生成引用原交易的冲正或补偿分录，绝不改历史。

总账平衡、余额投影、业务订单、链上托管资产、供应商余额和银行/支付凭证分别对账。差异进入人工复核，后台不能用“调余额”消除差异。
