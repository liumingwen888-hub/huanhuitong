# 用户旅程

需求状态：APPROVED。交付状态：DESIGNING。

## 首次进入与正常登录

用户发送 /start 或通过有效领取深链启动 Bot。平台以 Telegram user.id 查找绑定：已有绑定进入原 UID；未绑定则在一个幂等身份事务中创建 UID、会员关系、Telegram 绑定、最小用户资料和注册幂等记录，然后展示主菜单。重复 Update、Webhook 重试、并发 /start 只能得到同一结果。该事务不创建具体币种账本账户、链上地址、钱包、充提网络或换汇市场；注册成功也不要求所有未来资产账户已存在。正常登录、账号更换、丢失恢复、密码重置、未来 App 绑定和 UID 冲突处理是独立流程。

主菜单只展示已经批准并启用的资产能力。资产目录获批后，由应用编排调用账本公开接口幂等开通账户，或在用户首次使用某资产时懒创建；具体策略由资产与账本实施设计决定。交易对出现在产品目录不会触发余额账户创建。

## 已注册收款人转账

付款人选择一个可确认的已绑定 UID，页面显示平台 UID 的安全摘要与收款人确认信息。平台依次校验付款人状态、支付密码、风险、限额、资产、金额、费用与可用余额，原子预留并通过复式账本记账，生成双方账单。Telegram 通知从 Outbox 异步发送；通知失败不回滚已完成账本。

## 未注册收款人领取

付款人创建定向转账或红包后，平台预留资金并生成随机、不可猜测、一次性、可过期的领取凭证，只把不透明短令牌放入 Bot start 深链。付款人主动分享链接。收款人点击并启动 Bot 后，平台幂等注册或进入既有 UID，校验领取者约束与凭证状态，再经账本完成领取。到期或撤回按权威状态退回；同一凭证只能产生一次成功。

## 首次资金操作设置支付密码

当用户首次进入要求支付密码的资金操作时，原操作暂停，进入短期密码设置会话。用户在 Telegram 客户端用内联数字键盘连续输入两次；界面只显示位数。每次 callback_data 只携带映射单个输入动作的一次性随机令牌，不携带完整密码；专用凭证组件仅在短期内存中组合和验证原文，完成、取消或过期立即清除。两次一致且版本化哈希保存成功后，资金领域只接收绑定操作上下文的短期授权证明或引用，用户必须重新确认原操作或回到安全续接点。取消、不一致、过期、风险拒绝或保存失败都不得继续扣款。

输入动作会经过 Telegram 基础设施，因此 Bot 不能宣称支付密码对 Telegram 不可见，也不能把它视为独立于 Telegram 渠道的强认证设备。原文不得进入数据库、缓存、日志、追踪、错误、普通审计、Outbox/Inbox 正文、资金领域、客服/管理后台或消息回显。Telegram 账号或客户端被接管时，支付密码仍提供知识因子；高金额提现、敏感安全变更和账号恢复是否叠加 TOTP 或未来 App 强认证，由现有 P0 第 7、8 项决定。

## 充值

用户选择已支持资产和网络，取得地址或入账标识。扫描器去重观察链上交易，按确认水位和重组规则形成权威观察，满足条件后经账本入账。归集独立执行。错误网络或资产进入人工流程，不能猜测入账。

## 提现

用户提交资产、网络、地址和金额；平台校验支付密码、可选 TOTP、费用、风险与余额后预留资金。经审批、隔离签名、广播和确认流程完成。广播结果未知时冻结在不确定状态并主动查询，不释放资金也不重发。确定失败才释放或冲正。

## 换汇与法币代付

换汇先取得有期限报价，显示输入、预计所得、费用和舍入，确认后预留资金并执行。外部状态未知时查询和对账。法币代付按供应商能力、报价、建单、回调验真、主动查询和对账推进；UNKNOWN 不自动重付。完整状态由对应领域文档定义。
