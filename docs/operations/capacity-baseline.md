> **ENVIRONMENT_BOUNDARY**：本文数字均为合成容器环境产出。生产容量规划必须以生产硬件实测为准；基准方法可重复，生产实测后**替换**数字并追加到趋势表。

## 基准方法（可重复）

脚本：`scripts/benchmark-kernel.mjs`（需 Docker + 数据库 fixture）。

```bash
node scripts/benchmark-kernel.mjs --posting 100 --registrations 20 --queries 10
```

| 模式 | 测量 | 路径 |
|---|---|---|
| posting-tps | 顺序过账 TPS | 内核：行锁 → 余额校验 → 分录 → 投影 |
| concurrent-registration | 并发注册吞吐 | 注册幂等（inbox/绑定/UID 创建） |
| read-latency | 对账报告 p50/p99 | 三域只读对账路径 |

## 容量触发点（建议）

| 指标 | 阈值 | 动作 |
|---|---|---|
| 过账延迟 p99 | > 2s 持续 10 分钟 | 暂停新单（配置发布 max_amount=1）→ 诊断锁竞争/容量 → 恢复 |
| 注册 TPS | 下降 > 50% 对基线 | 检查连接池 → 索引 → 审计表膨胀 |
| 对账延迟 | 超时或 > 30s | 生产引入只读副本；对账不阻塞在线路径 |

## 降级预案

1. **过载**：配置发布降 max_amount（可逆止血）→ 告警 `posting-latency-degradation`（P2）触发 → 诊断 → 逐步恢复。
2. **注册退化**：`admin_api_denied` / 注册失败激增 → 连接池与索引排查——降级不停注册（新用户准入是收入）。
3. **读路径**：对账是后台任务，超时不影响在线交易；生产可迁只读副本。
